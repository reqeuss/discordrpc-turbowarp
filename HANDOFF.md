# Project handoff — Discord RPC for TurboWarp

This file is the compact source of truth for continuing work in another ChatGPT conversation. Read this before editing code.

## Goal

Connect a TurboWarp game to Discord Rich Presence through a local Python WebSocket bridge. The bridge is local-only at `127.0.0.1:32123`.

## Current layout

- `extension.js`: TurboWarp custom extension; must be loaded **unsandboxed**.
- `resources/rpc/rpc_bridge.py`: WebSocket server, process detection, Discord IPC, payload validation and reconnect handling.
- `resources/rpc/requirements.txt`: Python dependencies.
- `resources/rpc/config.example.json`: configuration template.
- `resources/rpc/config.json`: local config generated by `setup.bat`; ignored by Git.
- `setup.bat`: one-time Python/dependency/config setup.
- `game.bat`: starts the bridge and then `testdiscordrpc.exe`.
- `tests/test_rpc_bridge.py`: payload validation tests.
- `.github/workflows/ci.yml`: Python compile/tests and JavaScript syntax check.
- `README.md`: setup, extension blocks and troubleshooting.

## Protocol

Extension → bridge WebSocket JSON:
- `{"action":"update", ...}`: full snapshot of configured fields.
- `{"action":"clear"}`: clear the activity.

Fields:
- `details`, `state`
- `start`, `end`: Unix timestamps in seconds
- `largeImage`, `largeText`, `smallImage`, `smallText`
- `partyId`, `partySize`, `partyMax`
- `joinSecret`, `spectateSecret`, `instance`

The bridge maps camelCase JSON fields to pypresence's snake_case keyword arguments. Do not change the payload names in only one side; update both the extension and bridge together.

## Local setup

1. Put `testdiscordrpc.exe` in the project/game root.
2. Run `setup.bat` once; enter the numeric Discord Application ID.
3. In TurboWarp, add `extension.js` as a custom **unsandboxed** extension.
4. Run `game.bat`.
5. In the project, set fields then call `update presence`.

The Application ID is public configuration, not a bot token. Never add Discord tokens or other secrets to Git.

## Verification

Run from the project root:

```powershell
py -3 -m pip install -r resources/rpc/requirements.txt
py -3 -m py_compile resources/rpc/rpc_bridge.py
py -3 -m unittest discover -s tests -v
node --check extension.js
```

CI is configured to run the same checks. A successful syntax/unit-test run does **not** prove a live Discord IPC session works; that still needs a local test with Discord desktop and the game running.

## Known caveats / next verification

- Confirm CI has passed after the latest commit.
- Run `setup.bat` locally and verify `resources/rpc/config.json` contains the right app ID and game executable name.
- Test a presence update, change a field and update again, clear presence, close/reopen the game, and temporarily close/reopen Discord.
- Asset keys must exist in Discord Developer Portal Rich Presence Art Assets; URLs are not accepted as image keys.
- If an update fails, check the visible **Discord RPC Bridge** console.
- A browser request to `http://127.0.0.1:32123/` is not a valid test; the endpoint speaks WebSocket.
- Do not claim the integration is fully tested until it has been tested on the actual Windows game/Discord setup.
