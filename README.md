# Discord Rich Presence for TurboWarp

A local Python bridge connects a TurboWarp custom extension to the Discord desktop client's Rich Presence RPC.

## Features

- Set activity details and state.
- Set start/end timestamps (Unix seconds).
- Set large/small image asset keys and hover text.
- Set party ID, party size, and maximum party size.
- Set Join/Spectate secrets and the instance flag.
- Queue the latest update while the bridge or Discord is connecting.
- Reconnect the extension to the local WebSocket bridge automatically.
- Keep the bridge bound to `127.0.0.1` (not exposed to your LAN).

## First-time setup on Windows

1. Install the Discord desktop application and sign in.
2. Install Python 3 for Windows. Enable the Python launcher (`py`) during setup.
3. Put `extension.js` and the `resources/rpc` folder next to `testdiscordrpc.exe`.
4. Double-click `setup.bat`, enter your Discord Application ID, and wait for the dependencies to install.
5. Add `extension.js` to your TurboWarp project as a **custom unsandboxed extension**. The extension must be unsandboxed because it opens a local WebSocket connection.
6. Start the game with `game.bat` so the bridge and executable launch together.

The local `resources/rpc/config.json` is generated by setup and ignored by Git. To change the executable name, edit its `game_exe` value. Relative paths are resolved from the game folder. You can also set `DISCORD_APP_ID` or `DISCORD_GAME_EXE` environment variables to override the config.

## Extension blocks

- **set [field] to [value]** — configure an activity field.
- **update presence** — send all configured fields to the bridge.
- **clear presence** — clear the current activity.
- **reconnect to bridge** — retry the local WebSocket connection.
- **RPC connection status** — show extension-to-bridge connection status and the last error.
- **current value of [field]** — read a configured field.

Set all fields first, then call **update presence**. Timestamps are Unix timestamps in seconds, not milliseconds. Image fields must match asset keys configured in your Discord application's Rich Presence Art Assets. Image keys are not image URLs.

## Important limitations

- The bridge needs the Discord **desktop client** running; a browser tab alone is not enough.
- The Discord Application ID is not a bot token or client secret, but keep any real secrets out of the repository.
- Join/Spectate features depend on Discord's activity capabilities and valid secrets supplied by your game.
- A browser visiting `http://127.0.0.1:32123/` is not a valid health check. This endpoint speaks WebSocket, so use the extension's status reporter or the bridge console.
- This repository cannot verify a real Discord session in CI. Run the local test steps below after setup.

## Troubleshooting

**The bridge says the app ID is invalid**  
Run `setup.bat` and enter the numeric Application ID from the Discord Developer Portal.

**The game executable cannot be found**  
Make sure `testdiscordrpc.exe` is beside `game.bat`, or change `game_exe` in `resources/rpc/config.json`.

**The extension stays disconnected**  
Run `game.bat`, keep its **Discord RPC Bridge** console open, and confirm the extension is loaded unsandboxed. The bridge address is `ws://127.0.0.1:32123`.

**The connection works but the activity does not change**  
Check the bridge console for `[RPC] Update failed`. Confirm the Discord desktop app is open, the Application ID is correct, and image keys exist in the app's asset settings.

## Security

The bridge listens only on loopback (`127.0.0.1`) and does not implement a public network server. Do not change it to `0.0.0.0` unless you intentionally want to expose it to other devices.
